# 滑块轨迹理论（阿里云滑块拖动）

## 一、核心问题

> 人工拖动最难被机器模仿的特征是什么？

**用户原始直觉正确：加速 ↔ 减速的切换点最难模仿。**

---

## 二、判定裁决（verdict）体系

| 裁决 | 含义 |
|---|---|
| T001 | 通过 |
| F001 | 风控 |
| F015 | 位置误差 |
| EXC | 网络异常 |

- 位置误差 F015 说明后端校验**落点精度**；
- 风控 F001 说明后端校验**轨迹形态**（速度曲线、时间间隔分布）。

- `Input.dispatchMouseEvent` 注入拖动事件；
- 注入标记 `drag_source="cdp_auto"`；
- 目标：带阿里滑块验证码的注册页（AliyunCaptcha）。

## 四、CDP 几何映射

下滑块缺口识别出的是页面像素坐标 `piece.left`，与 CDP 实际鼠标位移是抛物线关系：

```
piece.left = A_CDP * m + B_CDP * m²
A_CDP = 0.0769
B_CDP = 0.003552
```

（`m` = CDP 鼠标移动距离）

## 六、feedback 轨迹变体（核心成果，当前默认）

通过**逐帧分析人工样本 idx12**，发现 4 个人工微结构，全部复现：

1. **整数量化噪声**：dx 被舍入到约 0.5px 网格，约 35% 的帧带 ±1 偏移；
2. **双峰速度波形**：峰值 → 深谷 → 二次加速 → 滑行；
3. **拖动中途犹豫暂停**：60–160ms，出现在 40–80% 进度处；
4. **末端回拉**：6–13 帧负 dx，总计 3–12px。

> 人不会像 AI 那样对准——**差不多就松手，要模拟误差**（末端回拉就是人手的自然误差）。

### 预处理

- 死帧清理：连续 0.01px 卡顿帧会被修剪，再重新分配 dx/dy；
- 距离守恒：修剪后总位移仍 = 目标位移 D。

### feedback 累计统计（2026-09-07，146 次滑块尝试）

- 尝试 146 次：T001=113，F001(风控)=21，F015(位置差)=8，EXC(网络)=4
- **滑块单次通过率 77.4%**（T001/全部尝试）
- **一次通过率 78.4%**
- YOLO 置信度 avg=0.947–0.952，落点误差 avg≈2.8px

### 置信区间（95%，Wilson 修正，n=146 尝试）

- 滑块单次通过率：77.4% ± 约 6.8% → **[70.6%, 84.2%]**

> 关键：风控收紧窗口下，combo 挂 0/9，feedback 5/5。
> 证明 feedback 复现的「加速↔减速切换」正是风控模型区分人机的核心特征。

### 失败归因（146 次尝试）

| 裁决 | 次数 | 归因 |
|---|---|---|
| F015 | 8 | YOLO 低置信识别偏差 → 落点错位（重试即过） |
| F001 | 21 | 轨迹风控偶发拦截（约 2/3 可重试兜底） |
| EXC | 4 | 页面导航破坏 / TLS 断连 |

> 结论：
> > 1. **位置类失败(F015) 100% 可重试兜底**；轨迹类失败(F001)约 2/3 兜底。
> > 2. 连续 F001 有「会话级粘性」（同一上下文被盯上就换环境，不硬磕）。

### F001 粘性检测（会话级）

连续 F001 有会话粘性：同一上下文被盯上后硬磕成功率极低。
对策：连续 2 次 F001 即中止当前会话、换环境重来——粘性中止在
第四批触发 1 次，下一个会话立即恢复通过。

## 八·五、离线打分闭环（第五批，event_count 闸门）

### 相关性研究（correlation_study.py, 224 次在线尝试）

聚合特征判别力（AUC，对全体失败）：

| 特征 | AUC | 通过均值 | 失败均值 |
|---|---|---|---|
| **event_count** | **0.818** | 63.7 | 79.9 |
| events_per_sec | 0.706 | 65.8 | 90.0 |
| avg_dt_ms | 0.706 | 16.4 | 13.0 |
| px_per_sec | 0.569 | 239.9 | 251.2 |
| yolo_conf | 0.502 | — | — |

事件数分桶（feedback 近三批 125 次）：

| 在线事件数 | 通过率 |
|---|---|
| < 50 | 100% |
| 50–60 | 83% |
| 60–70 | 77% |
| 70–80 | 72% |
| 80–90 | 60% |
| > 90 | 0% |

**单调递减：事件越多（采样越密）越像机器。**

### 关键事实：本地生成数 ≠ 在线到达数

- 本地生成器：中位 82 事件
- 在线实测：中位 62 事件
- **CDP/rAF 事件合并率 ≈ 27%**（本地 85 个 → 浏览器实际到达 62 个）
- 闸门必须按「预计在线到达数 = 本地数 × 0.73」计算，否则闸门形同虚设。

### 闸门实现（auto_batch.py solve_captcha 内）

```python
MERGE_RATE = 0.27       # CDP/rAF 合并率
ONLINE_SAFE_MAX = 60    # 预计在线数 <=60 直接交(83%+ 区间)
ONLINE_SOFT_MAX = 70    # 60-70 灰区: 重掷 1 次后接受
MAX_TRACK_REGEN = 6     # 兜底不阻塞
```

本地平均重生成 0.49 次/条，毫秒级开销。

### A/B 实测结果（第五批 3wy9s2, 20 号）

| 指标 | 基线(125 次) | 闸门批(19 次) | 差值 |
|---|---|---|---|
| **单次通过率** | 78.4% | 78.9% | **+0.5pp** |
| F001 风控率 | 15.2% | 15.8% | +0.6pp |
| 在线事件数中位 | 62 | 58 | -4 |

### 结论：闸门统计中性，原因与处置

1. **为什么没涨**：T001 vs F001 的 AUC 只有 **0.642**（弱判别）——
   之前 0.818 是把 F015(位置错)/EXC(异常) 混进失败算出来的假信号；
   风控对事件数的敏感度其实不高（F001 中位 66 vs T001 中位 62）。
2. **闸门仍有价值**：它把在线事件数中位从 62 压到 58（更安全区间），
   且成本为零（本地毫秒级）；样本量 19 还太小，+0.5pp 在噪声范围内。
3. **处置**：闸门保留（防事件数 >80 的高危轨迹），但承认它不是通过率的
   主要杠杆。F001 的主导因素仍是轨迹形态本身与会话粘性。

> 下一步的真正杠杆：补人工样本到 50 条 → 用全 59 维特征训练分类器 →
> 对轨迹「形态」打分（而非单事件数），才可能把 78% 推向 85%+。

## 九、实验纪律

- **每次只改一个变量**：轨迹变体 与 IP 不同时换，保证对照有效性；
- feedback 是默认；combo 留作对照组；
- 人工样本 label 永远是「人类」=1，绝不把线上 T001/F001 当训练标签
 （否则会训练出「模仿被判过」的过拟合模型）。

## 九·五、形态重构：从聚合统计到真机形态（2026-09-07 晚）

### 动机：打分器完美可分的启示

用 30 条人工样本（label=1）vs 180 条生成轨迹（label=0）训练随机森林：

- **AUC = 1.000，完美可分**（人工最低分 0.983，生成最高分 0.170）
- 结论：我们的轨迹在形态特征上与真人**完全不同分布**，
  之前的 78% 通过率是风控模型不够敏感，不是我们像人。

### 特征差距清单（shape_gap_diagnosis，7 个机器指纹）

| 特征 | 真人 p50 | 生成 p50 | 诊断 |
|---|---|---|---|
| pre_release_micro | **0**（30 条全 0） | 0.25 | 我们发明的"松手前微动作"真人根本没有 |
| peak_speed_pos | **0.745** | 0.213 | 真人峰值速度在 75% 进度（末端甩鞭），我们前载爆发完全错误 |
| speed_max | 9722 px/s | 1420 | 真人峰值快 7 倍——甩鞭一瞬 30~50px/4ms |
| y_std（y 路径 std） | 38 | 2.2 | 真人手臂漂移大 17 倍 |
| zero_dx_ratio | 4.1% | 0% | 真人 4% 帧完全静止（我们不自信的 0.01px 钳位暴露自己） |
| speed_reversal_count | 6 | 1 | 真人中途多次反向微调（对位置） |
| dt_min | 1.0~2.2ms | 3.0 | 3ms 钳位是指纹 |

### 正确的真机形态模型

**"慢逼近 → 谷底犹豫 → 末端甩鞭 → 收尾"**，而非"前载爆发+滑行"：

1. 前段（45~60% 帧）：**显式距离预算 15~30%**（关键！按帧切分会让
   前载曲线吃掉 60~85% 距离——debug_flick 实测的坑）；
2. 谷底（3~6 帧 × 40~110ms）：看缺口；
3. 甩鞭（16~28 帧 × 2.5~6ms，窄驼峰 σ=0.07~0.11）：距离的 65~75%
   在 ~100ms 内砸完，峰值 5000~15000 px/s；
4. 收尾（5~10 帧）：中速滑行；可选末端回拉；
5. y 轴：**手臂线性漂移**（不是振荡！）——向上为主（滑块贴近组件底部，
   向下漂出 iframe 会断拖）；
6. dt 分布：65% @ 3.5~6.5ms + 宽尾巴（dt_cv 2.7），下限 1.2ms。

### 重构效果（五轮诊断迭代）

| 指标 | 重构前 | 重构后 | 真人 |
|---|---|---|---|
| peak_speed_pos | 0.213 | **0.773** | 0.745 ✓ |
| speed_max | 1420 | **8922** | 9722 ✓ |
| y_std | 2.2 | **43** | 38 ✓ |
| pre_release_micro | 0.25 | **0** | 0 ✓ |
| zero_dx_ratio | 0 | 0.052 | 0.041 ✓ |
| dt_min | 3.0 | 1.6 | 1.5 ✓ |
| 事件数 | 65 | 84 | 127（仍偏低） |

### 同期修复的工程问题

- **注入层 y bug**：`sy + dy`（每帧增量）而非累计路径——y 形态从未真正上线；
- **落点方向**：偏负落点 F001 率 71% vs 偏正 54% → 落点只偏正。

### 方法论沉淀

- **分类器不是闸门，是诊断仪**：AUC=1.0 时闸门无意义（会拒掉一切），
  但特征重要性 = 精确的"像人差距清单"，按清单逐项修生成器；
- 修完重训 → 特征重要性换血 → 继续修下一批（迭代收敛）；
- 形态指标对齐后，最终裁判仍是线上 T001 率（离线分布像 ≠ 风控放行）。
